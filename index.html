01 · Motivation

The targeting problem

Surveys are expensive and quickly outdated. Proxy Means Test (PMT) rules are linear and hand-crafted. Poor targeting leaves the poor out and wastes budget.

Costly & Outdated Surveys

Full consumption censuses take years to collect and rapidly lose accuracy after economic shocks.

Rigid Linear PMT Rules

Proxy Means Tests rely on hand-crafted linear weights that miss non-linear household interactions.

High Human & Fiscal Cost

Misclassification either denies critical assistance to vulnerable families or leaks scarce programme funds.

Exclusion Error

Primary fairness metric
Exclusion Error = FN / (FN + TP)

A poor household is wrongly denied aid. This is the primary fairness metric.

Inclusion Error

Budget leakage metric
Inclusion Error = FP / (FP + TN)

A non-poor household is wrongly included, which causes budget leakage.

03 · Methodology

End-to-end modelling pipeline

Select any stage below to inspect the data transformations, model hyperparameters, and calibration rules.

Load household and individual CSVs.
Aggregate individual numeric columns to household level (mean, min, max, sum) and add hh_size.
Impute with column means (then -999), and LabelEncode categoricals.
PMT baseline: Logistic Regression (max_iter 1000) on StandardScaler features, 0.5 cutoff.
LightGBM: learning_rate 0.05, max_depth 6, num_leaves 31, feature_fraction 0.8, up to 1000 rounds with early stopping at 50, and scale_pos_weight = #non-poor/#poor.
Dynamic threshold: Percentile(OOF_Preds, (1 − poverty_rate) × 100), so the share predicted poor matches the observed poverty rate.
Evaluate: Log Loss, ROC-AUC, accuracy, F1, exclusion and inclusion error, and household-size subgroups.

Disparity Analysis

Hypothesis, not a proven cause
  • Small households are excluded most in A and C. In C the rate is about 5x that of other groups.

The reference API reads the files in memory and does not store them. Only upload data you are allowed to share with the server you connect to.

What files do I need?

  • Two CSVs for the same country, in the same layout as the Pover-T *_hhold_train.csv and *_indiv_train.csv files.
  • Both files need an id column. The individual file has one row per person.
  • An optional poor column in the household file (True/False) also returns accuracy, exclusion error and inclusion error.
  • Column names are anonymised, so households cannot be typed in by hand. Each country model only accepts its own columns.
Accuracy figures are only meaningful for households the model has not seen. Sample files cut from the training data will score unrealistically well.

    09 · Synthesis & Critical Reflection

    Recommendations, limitations and future work

    Translating empirical findings into actionable deployment guidance while transparently documenting methodological constraints.

    01 · Fairness Calibration

    Subgroup Thresholding

    Lower thresholds for small households.

    02 · Cutoff Caveat

    Percentile Calibration

    Use poverty-rate percentile thresholds, but note that they don't guarantee low exclusion (see Country B).

    03 · Data & Survey Design

    Country B Remediation

    Country B needs more poor-household data, better survey questions and budget-based thresholds.

    Methodological limitations

    • No held-out test set.
    • Imputation and scaler fitted before cross-validation (mild leakage).
    • Unequal PMT and LightGBM cutoffs.
    • Only 251 poor households in Country B.
    • Fairness audited only by household size.

    Future work

    Next steps to harden validation rigor, model interpretability, and policy alignment:
